# 核心循环系统 GDD · 《WASTELAND ESCAPE / 废土逃生》

> 系统名：Core Loop（核心循环）｜ 阶段：Phase 2 系统设计 ｜ 评审强度：lean
> 依赖决策：D1 黄昏/夜晚基调 · D2 2.5D 伪3D 三轨背后视角（神庙逃亡结构）· D3 单指滑动操作 · D4 单局无限距离+跨局里程碑
> 服务支柱：P1 一指即达 / P2 风险即奖励 / P3 30 秒一局成长感（本系统为三系统总编排器）

---

## 1. 概述与目标
- **定位**：核心循环是单局的"生命线编排器"——驱动三轨自动前进、串联障碍生成与连击计分、管理顶层状态机与三轨切轨 / 过弯 / 死亡 / 重开。它不直接定义障碍或倍率，而是让两者按统一节奏咬合。
- **对齐支柱**：
  - **P1（一指即达）**：所有动作由单指滑动 / 键盘方向键触发；本系统保证"不新增必须学才能玩的输入"。
  - **P2（风险即奖励）**：本系统把障碍生成产出的"近失事件"与连击计分桥接，使贴脸行为有回报通路。
  - **P3（30 秒一局成长感）**：死亡→重开零等待（< 2s），每局距离 / 最佳可见，难度平滑。
- **解决的玩家问题**：让"跑→切轨/跳/滑/过弯→躲/收→连/刷→重开"动词链闭环；单局目标按 **D4** = 纯无限距离（刷新单局记录）+ 跨局累计里程碑解锁。
- **主题换皮（丧尸末日）**：本系统为纯玩法编排，与美术包装解耦——障碍 / 收集按美术圣经丧尸向重命名（钢筋尖刺 / 断梁 / 横杆 / 游荡丧尸、补给 / 急救包），**核心循环、动作、状态机、事件接口完全不变**；新增的激励视频钩子见 §6.1。

## 2. 核心机制
### 2.1 顶层状态机
```
BOOT → MENU → COUNTDOWN → RUNNING ⇄ CORNER(过弯子状态)
                          │
                          │ FATAL_HIT
                          ▼
                       RESULT ──(REVIVE 可选)──▶ RUNNING
                          │
                          │ (restart)
                          ▼
                      COUNTDOWN ──▶ RUNNING
```
- **RUNNING** 为唯一活跃玩法态；**CORNER** 是 RUNNING 内的过弯子状态（见 §2.6），不离开 RUNNING。
- **REVIVE** 仅作为 RESULT 态的可选分支（看广告复活后回 RUNNING）；无广告 / 拒绝则直接进入 restart 流程。
- MENU 仅承载"开始 / 最佳展示"，不阻塞核心循环（无冗长菜单）；COUNTDOWN 提供 3-2-1-GO 入场缓冲（P3 零卡顿，但给玩家读图窗口）。

### 2.2 玩家子状态（RUNNING 内）
`GROUND_RUN → LANE_CHANGE(平滑插值) → JUMP(rising/falling) → [DOUBLE_JUMP] → SLIDE → CORNER(锁定中轨)`
- MVP 仅暴露 `GROUND_RUN / LANE_CHANGE / JUMP / SLIDE`；`DOUBLE_JUMP` 与 `CORNER` 为核心档（二段跳、过弯转角），由动作集门控 `tier` 控制，见 §7。
- 切轨与跳 / 滑可并行（边切轨边跳），但切轨期间不可再触发过弯（过弯会强制锁中轨）。

### 2.3 数据流（三系统咬合）
```
[ObstacleGen] --spawn--> 世界实体
      │                         │
      │ (NEAR_MISS / FATAL / PICKUP 事件)
      ▼                         ▼
[CoreLoop] 路由事件 ──► [ComboScoring] 更新 combo / 倍率 m
      │                         │
      │ 每帧: d += V·dt；lane 插值；score += V·dt·m
      ▼                         ▼
   HUD(距离/分数/连击/轨道)   ←───  持久化(最佳记录/累计里程碑 D4)
```
- 每帧核心循环：推进距离 `d += V·dt`；三轨横向位置按 `lane` 目标值平滑插值（不影响 `V`）；向 ComboScoring 推进衰减窗口 tick；向 ObstacleGen 提供 `(V, d, tier, lane)` 以驱动生成节奏与过弯段避让。

### 2.4 速度模型（单一真值源，供三系统共用）
```
V(d, combo) = min(Vmax, V0 + k_d·d) · (1 + k_c·min(combo, comboFlowCap))
```
- 详见 §4 初值。ObstacleGen 的"最小间隔"与 ComboScoring 的"衰减窗口"均依赖 `V`，故 `V` 只在本系统定义，避免三处数值打架（一致性红线）。
- **三轨下语义**：速度 `V` 沿赛道纵深推进，是玩家前进的唯一速度；**切轨（横向 lane 移动）不影响 `V`**，仅改变横向位置（追尾视角下横向位移为插值，不计入距离 `d`）。

### 2.5 三轨坐标与切轨（核心契约）
- **轨道集合**：`lane ∈ {0, 1, 2}`，分别对应 左 / 中 / 右。
- **世界坐标**：横向偏移 `x_lane = (lane - 1) · laneWidth`（中轨为赛道中线 `x=0`）；玩家横向渲染位置 `x` 向目标 `x_lane` 平滑插值（指数平滑或固定速度，`laneLerp` 见 §4），不瞬移、不跨轨。
- **输入约束**：左右滑在相邻轨间切换（`lane ± 1`，夹紧到 `[0,2]`）；不可一次跨两轨。
- **P1 保证**：MVP 仅需"左右滑 + 上滑 + 下滑"三个手势即可存活；切轨 / 跳 / 滑均为单指手势，无新按键。

### 2.6 过弯机制（CORNER 子状态 · 核心档）
- **赛道分段**：赛道由 `segment` 序列组成，每个 segment 含转角属性 `turn ∈ {left, right, straight}` 与长度 `segLen`。
- **进入 CORNER**：当 RUNNING 推进进入 `turn ≠ straight` 的 segment 时，进入 CORNER 子状态：
  1. **锁定中轨**：强制 `lane = 1`（若当前不在中轨，先插值回中轨再进入转角，或转角入口即钳制）。
  2. **视角旋转**：相机 / 赛道视觉绕纵深轴旋转 `cornerTurnAngle`（如 ±90°），营造转弯感官（Sensation）。
  3. **暂停横向输入**：物理 tick 中**暂停横向输入**（左右滑切轨被忽略），但前进 `V` 与 跳 / 滑 物理 tick 继续——玩家仍可在转角中跳 / 滑躲避中轨障碍。
- **退出 CORNER**：segment 走完（`d` 越过 `segLen`）→ 解除中轨锁定与横向输入暂停，恢复可切轨；若下一段仍为转角，连续衔接（视觉旋转累计）。
- **生成契约（待 obstacle-gen 协同）**：CORNER 期间 CoreLoop 向 ObstacleGen 置 `inCorner=true` 标志；ObstacleGen 在此区间**仅允许中轨跳 / 滑障碍**（断梁 / 横杆 / 尖刺），**不得生成需要左右切轨规避的障碍**（如仅某侧轨道的游荡丧尸），避免"锁中轨 + 必须切轨"的不可解组合。该契约需 obstacle-gen GDD 在 §2.2 门控中落实（见 §8 C-OBST，已 RESOLVED）。

## 3. 输入与控制（基于 D3）
| 平台 | 手势/按键 | 动作 | 备注（P1 不新增输入） |
|---|---|---|---|
| 触屏 | 左右滑（← / →） | 切相邻轨 | 单指即可；三角色夹紧 |
| 触屏 | 上滑（短） | 矮跳 | 单指即可 |
| 触屏 | 上滑（长/按住） | 高跳 | 按住时长→高度映射 |
| 触屏 | 空中再次上滑 | 二段跳 | 同一手势时序组合（核心档，非新手势） |
| 触屏 | 下滑 | 滑铲 | 单指即可 |
| 桌面 | ← / → | 切相邻轨 | 方向键等价 |
| 桌面 | ↑（点按 / 按住） | 矮跳 / 高跳 | 单键最低门槛 |
| 桌面 | ↑（空中再按） | 二段跳 | 时序组合 |
| 桌面 | ↓ | 滑铲 | — |

- **P1 保证**：MVP 仅需"左右滑 + 上滑 + 下滑"三个手势即可存活；二段跳 = 空中再次上滑（同一手势的时序组合），**未引入任何新按键 / 新手势**，复杂度来自组合与时机，符合 P1。
- **过弯输入处理**：CORNER 子状态下左右滑被忽略（横向输入暂停），仅跳 / 滑与前进生效，避免误切轨致死。
- 多指 / 误触：仅识别主指手势，忽略第二触点；手势去抖（最小位移阈值 + 最小时长阈值）避免滚动误判。

## 5. 边界与失败处理
- **死亡定义（呼应 P2 "单次失误不直接致死"）**：仅"实际碰撞致命障碍"=局终。**失误 ≠ 碰撞**——一次跳歪但仍擦过（未碰撞）的跳跃不构成死亡，只是可能错失近失奖励。近失尝试若失败（真撞上）= 死亡，此即 P2 真实代价。
- **重开逻辑（P3 零等待）**：RESULT 态一键→清空世界实体 / 连击 / 距离，保留 `localStorage` 中的最佳记录与跨局累计里程碑；不重新加载场景资源（对象池复用），确保 < 2s。
- **边界 / 边缘情况**：
  1. 网页切后台（tab blur）：暂停物理 tick，回前台恢复，避免"回来即死"。
  2. `localStorage` 不可用 / 写入失败：降级为内存记录，不阻塞游戏，仅提示"本次成绩不留存"。
  3. 速度 `V` 为 0 的除零保护（理论上不会，但防御性 `max(V, ε)`）。
  4. 长局分数溢出：计分用 64 位整数 / 双精度，封顶显示格式化（k/m）。
  5. **过弯中断**：若玩家在 CORNER 子状态内死亡 → 进 RESULT 并清除 CORNER 锁定 / 视角旋转状态，避免下一局残留转角偏移。
  6. **连续转角**：相邻 turn segment 连续时，视角旋转累计、中轨锁定持续，直至回到 `straight` 段才解除；生成器在此期间持续 `inCorner=true`。
  7. **切轨与过弯竞态**：进入 CORNER 的前一帧若玩家正在 LANE_CHANGE，先完成回中轨插值再锁死，避免半途卡轨。

## 6. 与其他系统的耦合
| 接口 | 方向 | 内容 |
|---|---|---|
| CoreLoop → ObstacleGen | 调用+供参 | `ObstacleGen.update(dt, V, d, tier, lane, inCorner)`；提供当前 `V`、`d`、动作集 `tier`、`lane`、过弯标志 `inCorner` 用于生成门控与避让 |
| ObstacleGen → CoreLoop | 事件 | `SPAWN`、`FATAL_HIT`、`NEAR_MISS(proximity)`、`PICKUP(type)` |
| CoreLoop → ComboScoring | 路由+驱动 | 转发 `NEAR_MISS`/`PICKUP`/技巧事件（`DOUBLE_JUMP`）；每帧 `ComboScoring.tick(dt)` 推进衰减窗口；提供 `V` 供计分 |
| ComboScoring → CoreLoop | 读 | `m`（倍率）供 HUD 与计分；`combo` 供流速加成 `k_c` |
| CoreLoop → 持久化 | 写 | 最佳距离、累计里程碑（D4） |

- **触发点**：`FATAL_HIT` 触发状态机→RESULT；`NEAR_MISS`/`PICKUP` 触发 ComboScoring 累加；`m` 每帧参与计分；`inCorner` 标志驱动 ObstacleGen 转角段避让。

### 6.1 广告/复活系统（核心档 · 激励视频 / rewarded video）
> 仅在**核心档**启用；**MVP 无任何广告**。Web/HTML5 / 小程序平台激励视频走 H5 广告 SDK / 发行平台，由工程侧评估接入；本 GDD 只定义行为与触发，不绑定具体 SDK。

- **触发位置（关键）**：`revive` **仅在 RESULT 状态触发**（与架构侧 ADR-005 / architecture §8.3 一致——RESULT 态世界已冻结，无穿隧风险）；`double` / `milestone` 在结算 / 里程碑点触发。
- **三个触发点（reason）**：
  1. **死亡复活 `revive`**：`FATAL_HIT` → RESULT 时，若本局 `rvRevivePerRun` 未用且 `rvDailyCap` 未达 → 提供"看广告复活续跑"。完成 → 玩家在死亡点（回退少许）以短暂无敌（~1s）复活，`combo` 归零、距离保留，清附近障碍；标记本局复活已用，**恢复 RUNNING**（复活时暂停物理 tick，广告关闭后恢复）。
  2. **结算翻倍 `double`**：RESULT 结算时"看广告使本局补给翻倍" → 完成 → 本局 earned `supply` ×2 写入累计（供核心档解锁）。
  3. **里程碑奖励 `milestone`**：跨局累计里程碑触发时"看广告领额外奖励"（补给 / 解锁折扣）→ 完成 → 奖励计入累计进度。
- **频率上限（防滥用，与架构侧对齐）**：
  - 每局复活 ≤ `rvRevivePerRun`（=1）；复活后本局再死亡直接终局，不再提供复活。
  - 每局翻倍 ≤ 1 次。
  - 每里程碑事件 ≤ 1 次（受里程碑频率自然限制）。
  - **每日总观看 ≤ `rvDailyCap`（=3，已统一）**，按日期戳存 `SaveManager`（`revive_count_today` + `last_revive_date`），跨日重置。**每日上限原文档误写为 10，本次已更正为 3，与架构侧 `revive_daily_cap=3`（architecture.md §8.3 / §8.4、control-manifest、ADR-005 §6）严格对齐，可按平台政策配置。**
- **与 SaveManager 衔接（命名空间 `wasteland_escape_save`，隔离 CMP 键，见 ADR-004）**：复用现有最佳记录 / 累计里程碑持久化层；新增键 `revive_count_today` + `last_revive_date`（每日上限）；`rv_revive_used` / `rv_double_used` 为局内内存标记（不跨局）。**仅奖励到账后写计数（不每帧）**，与 ADR-005 §6 / architecture §8.4 一致；复活不改最佳记录逻辑（距离延续）；翻倍 / 里程碑奖励计入累计补给（用于核心档解锁）。
- **暂停物理 tick**：请求广告前 pause（RESULT 态世界本已冻结；若未来在前台态请求则 `get_tree().paused=true` 或停 CoreLoop 物理），复活仅发生在 RESULT 态，故无穿隧风险；广告关闭后依结果恢复 RUNNING（清附近障碍 + ~1s 无敌）或维持 RESULT（见 ADR-005 §5）。
- **接口（lean，不绑 SDK）**：
  - `AdSystem.requestRewarded(reason: 'revive'|'double'|'milestone', onGranted: () => void, onDeclined: () => void)` — 异步；由发行平台 H5 广告 SDK 实现（工程评估）。`onGranted` 才发奖；`onDeclined`/失败不发奖、不消耗本局机会（每日上限除外）。
- **耦合**：CoreLoop 在 `FATAL_HIT` / 结算 / 里程碑 三个点调用 `AdSystem`；ComboScoring / 持久化 提供翻倍与奖励写入（见 combo-scoring §4 `supplyBonus`、§7 核心档）。

## 7. 范围分层
- **MVP**：三轨自动前进 + 切轨 + 跳 + 滑 + 死亡 + 一键重开 + 距离 HUD + 本地最佳记录；单一场景、单一速度曲线、**无过弯**；`tier=MVP`（无二段跳 / 过弯 / 近失加成）。
- **核心**：+ 过弯转角（CORNER 子状态）+ 二段跳 + 连击流速加成 `k_c` + 跨局里程碑解锁（D4）+ 多场景（昼夜 / 速度分段）+ 近失 / 急救包连击 + **激励视频钩子（复活 / 翻倍 / 里程碑，见 §6.1）**。
- **延展**：每日挑战、异步排行榜（需后端）、无障碍模式（自动滑铲 / 减速 / 色盲配色）。

## 9. 跨 GDD 一致性评审（三系统合审）
> 评审对象：core-loop / combo-scoring / obstacle-gen 三份 GDD 与锁定背景（概念文档、D1–D4、Phase1 汇编、架构侧 ADR-004/005）。

### 9.1 支柱服务判定
| 支柱 | core-loop | combo-scoring | obstacle-gen | 结论 |
|---|---|---|---|---|
| P1 一指即达 | ✅ 单指手势覆盖全动作、无新输入 | ✅ 连击无独立输入，纯被动计分 | ✅ 可读性强轮廓、动作集门控防不可解 | PASS |
| P2 风险即奖励 | ✅ 桥接近失事件 | ✅ 近失高回报+衰减软压力 | ✅ 预留近失接入点+安全/风险双路线 | PASS |
| P3 30秒成长 | ✅ 零等待重开+可见成长 | ✅ 距离×倍率即时反馈 | ✅ 平滑难度+动作分层 | PASS |

### 9.2 主导策略（是否存在唯一最优解）
- **判定：无主导策略（PASS）**。安全路线（以充裕余量通过障碍、不蹭近失）始终可行但连击 / 倍率低；风险路线（贴脸近失）高回报，但近失失败即真实碰撞=死亡，代价真实存在。两路线并存且有真实权衡，符合 P2。
- **CONCERN（非阻塞）**：近失带宽 `nearMissBand` 若调得过大，可能使"贴脸"几乎无风险→事实主导策略。已标注为 playtest 调参项，需实测校准。

### 9.3 经济失衡（MVP 无付费）
- **判定：PASS**。MVP 无付费；核心档引入**激励视频**（复活 / 翻倍 / 里程碑，频率上限防滥用，见 §6.1），无 IAP、无付费加速；补给解锁与里程碑并行，无强制付费墙。经济为轻量广告钩子，未引入付费失衡。

### 9.4 早期认知过载（动作是否分层引入）
- **判定：PASS**。`tier=MVP` 仅切轨 + 跳 + 滑三个手势；二段跳 / 过弯 / 近失加成门控在核心档，并建议在 ~第 3–5 局后逐步引入（呼应概念文档心流设计），无早期强制多动作。

### 9.5 支柱漂移（是否引入剧情/社交）
- **判定：PASS**。三份 GDD 均未引入叙事系统、PvP、强社交系统；丧尸末日仅为视觉 / 叙事包装（无剧情进度 / 对话），不污染核心支柱；延展档的"异步排行榜 / 社区路线"明确标注需后端且谨慎评估。
