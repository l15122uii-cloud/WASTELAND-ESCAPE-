# 连击计分系统 GDD · 《WASTELAND ESCAPE / 废土逃生》

> 系统名：Combo & Scoring（连击计分）｜ 阶段：Phase 2 系统设计（三轨变体重构）｜ 评审强度：lean
> 依赖决策：D2 2.5D 伪3D 三轨背后视角 / D3 单指滑动操作（左右滑切轨 + 上下滑跳/滑）/ D4 跨局里程碑
> 服务支柱：**P2 风险即奖励（主打）** / P3 30 秒一局成长感（次打） / P1 一指即达（无独立输入）
> 重构注记：本文件为「2D 横版单线」→「2.5D 三轨背后视角（神庙逃亡式）」变体。连击状态机、倍率 `m(combo)`、衰减窗口 `T=2.5s` 保持不变；仅将「近失」与「计分事件」改写为三轨语义，并明确「连击在当前轨累计、跨轨切轨不中断」。

---

## 1. 概述与目标
- **定位**：把"动作密度"与"贴脸风险"转化为可读的分数与倍率。它是 P2 的计分引擎——奖励持续动作与近失，惩罚停滞，但不以死亡惩罚。
- **对齐支柱**：
  - **P2（风险即奖励）**：近失（贴脸通过）给超额连击与加分；停滞（不动作）则连击衰减清零——"不能停"的压力来自衰减而非死亡。三轨下近失分两类：同轨擦过（高风险高回报，含贴脸分层）+ 相邻轨掠过（低风险 +1），共同构成 P2 的通路。
  - **P3（成长感）**：分数 = 距离 × 实时倍率，每帧可见增长；本地最佳与累计里程碑（D4）给出清晰精通反馈。
  - **P1（一指即达）**：连击系统**无任何独立输入**——玩家只做滑动手势（切轨/跳/滑），连击被动累计，不新增学习负担。
- **三轨新增语义**：连击为**全局单计数器**，在玩家**当前轨**累计；跨轨连续切轨**不中断**连击（切轨本身既非计分事件、也非断连事件）。近失在三轨下有两种来源（见 §2.2），是「风险即奖励」主轴。
- **解决的玩家问题**：让"为什么我要一直动/为什么要贴脸"有数值答案；提供即时、可量化的精通信号（Achiever 驱动）。

## 2. 核心机制
### 2.1 连击状态机
```
IDLE(combo=0, m=1.0) ──scoring event──► BUILDING(combo>0)
BUILDING ──scoring event──► BUILDING (刷新衰减窗口)
BUILDING ──窗口 T 到期──► IDLE (连击清零, m 回 1.0)  ← 非致命软压力
BUILDING ──FATAL_HIT──► 局终 (连击随局结束, 规则保留)
```
- **关键设计**：概念文档写"撞致命障清零"，但致命碰撞=局终，局内连击压力必须另有来源 → 采用**衰减窗口**实现 P2 的"动作密度压力"，且单次失误（跳歪但没撞）= 无惩罚（仅可能错失近失），契合"单次失误不直接致死"。
- **三轨补充**：切轨（`LANE_SWITCH`）不改变状态机——既不产生事件也不触发清零。"连击在当前轨累计"指所有计分事件的判定，以玩家越过障碍/拾取时的**当前所在轨**为参考（同轨擦过 / 相邻轨掠过 / 当前轨拾取）。连续切轨不会因切换本身断连。

### 2.2 计分事件（驱动 combo 的源，三轨语义重写）
| 事件 | 来源 | combo 增量 | 说明 |
|---|---|---|---|
| 拾取补给 `PICKUP(supply)` | ObstacleGen/世界 | +1 | 在玩家**当前轨**拾取该轨收集物 |
| 拾取急救包 `PICKUP(medkit)` | 世界 | +2 | 核心档；常置于"开放但被障碍夹击的风险轨"，收集=贴脸冒险（见 §7） |
| 近失·同轨擦过 `NEAR_MISS(graze)` | ObstacleGen | +1（远）/ +2（近） | 当前轨障碍经跳/滑擦过；`d≤nearMissTier` 为贴脸(+2) |
| 近失·相邻轨掠过 `NEAR_MISS(flank)` | ObstacleGen | +1 | 障碍在相邻轨、玩家未撞上即触发（低风险） |
| 技巧：二段跳 `DOUBLE_JUMP` | CoreLoop | +1 | 核心档（可选计分，与 core-loop 定义一致） |

- **三轨近失判定（单一事实源 `nearMissBand/Tier`，见 obstacle-gen §4）**：在障碍越过玩家判定面的瞬间，取玩家碰撞壳与该障碍碰撞壳的**最小净空 `d`**（世界像素）。同轨擦过 = 纵向/垂直净空（可变，可贴脸）；相邻轨掠过 = 横向净空（几何常量）。`0<d≤nearMissBand` → 近失；`d≤nearMissTier` → 贴脸(+2)。相邻轨横向净空默认落在 band 内 → 恒触发 +1（见 §8 几何依赖）。
- **切轨不计入事件**：`LANE_SWITCH` 既不加 combo 也不清零；"连续切轨"不会因切换本身断连——连击归属只随计分事件（近失/拾取/技巧）推进。

### 2.3 倍率与计分公式
```
m(combo) = min(m_max, 1 + step·combo)        // 线性+软封顶
score   += V · dt · m                          // 每帧距离分×倍率
score   += Σ eventBonus                        // 事件额外加分
```
- 详见 §4 初值。`V` 由 CoreLoop 速度模型 `V(d,combo)` 提供（单一真值源，本系统只读）。

## 3. 输入与控制（基于 D3 / P1）
- **本系统无直接输入**。所有连击来自 CoreLoop 转发的移动/拾取/近失事件。玩家的"风险表达"（贴脸）通过 CoreLoop 的滑动手势完成，连击系统纯被动消费——这从机制上保证了 P1"不新增必须学才能玩的输入"。
- 唯一"玩家可控"的是行为选择：走安全余量线（低 combo，多为相邻轨掠过 +1）还是贴脸线（同轨擦过高风险高回报，赌 +2）。切轨是 P1 单指滑动的一部分，连击系统对其透明。

## 4. 关键数值与参数初值
| 变量 | 含义 | 初值 | 单位 | 备注 |
|---|---|---|---|---|
| `step` | 每连击倍率增量 | 0.10 | — | — |
| `m_max` | 倍率软封顶 | 5.0 | — | 达 combo=40 封顶 |
| `comboCap` | 线性段封顶 combo | 40 | — | 超出后维持 m_max |
| `T` | 连失/衰减窗口 | 2.5 | s | 每个计分事件刷新；到期清零。**前期需更宽松（见 §7）** |
| `nearMissBand` | 近失判定外缘 | 24 | px(世界) | **引用 obstacle-gen §4 真值**（三轨下=壳间最小净空；≈0.48m @ PPM=50）；`0<d≤24` 即近失 |
| `nearMissTier` | 贴脸分层阈值 | 12 | px | **引用 obstacle-gen §4 真值**；`≤12` 为"贴脸"(+2)，否则(+1) |
| 补给 `supplyBonus` | 补给加分 | 10 | 分 | 额外加成（独立于距离分） |
| 急救包 `medkitBonus` | 急救包加分 | 25 | 分 | — |
| 近失 `nearMissBonus` | 近失加分 | 15/30 | 分 | 远/近（flank 计远档 15；graze 远 15 / 贴脸 30） |
| 最佳记录 | 本地持久化 | — | — | D4 单局最佳距离/分数 |
| 里程碑阈值 | 跨局累计（D4） | 见 §7 | — | 累计距离/最佳/连击峰值 |

> 倍率/衰减/近失阈值均为**可调 playtest 项**，不在 R4 性能预算内（非帧预算相关），但需实测防主导策略。补给/急救包走独立拾取物对象池（见 obstacle-gen `pickupPoolSize=32`），不挤占障碍池 `poolSize`。`nearMissBand/Tier` 与 `PPM=50` 的真值分别由 obstacle-gen / core-loop 定义，本系统仅引用，避免跨 GDD 数值漂移（一致性红线）。

## 5. 边界与失败处理
- **致命碰撞**：`FATAL_HIT` → 局终，连击随局结束（规则保留与概念一致，局内不再单独处理）。
- **衰减清零**：窗口 `T` 到期 → `combo=0, m=1.0`（非致命，仅失去倍率）。
- **近失误判防护**：碰撞检测优先级高于近失——只有"未碰撞且 `0<d≤band`"才计近失，杜绝"撞上也算近失"的作弊/误判。三轨细化：同轨擦过需先判该轨碰撞（跳/滑是否成功），成功擦过才计近失；相邻轨掠过天然无碰撞（不同轨）。
- **长局溢出**：分数用 64 位/双精度，显示格式化（k/m）。
- **localStorage 失败**：最佳记录降级内存，不阻塞。
- **边缘情况**：同帧多事件（如拾币+近失同帧）→ 累加不丢；窗口在暂停（tab blur）时不走时；**过弯锁定中轨（CORNER）期间**，玩家在中轨，障碍仅在中轨生成且跳/滑可解，故该段近失来源 = 中轨擦过（+1/+2），相邻轨无生成、无 flank 近失。

## 6. 与其他系统的耦合
| 接口 | 方向 | 内容 |
|---|---|---|
| ObstacleGen → ComboScoring | 事件 | `NEAR_MISS(proximity{graze\|flank})`、`PICKUP(supply/medkit{lane})` |
| CoreLoop → ComboScoring | 路由+驱动 | 转发技巧事件（`DOUBLE_JUMP`）；每帧 `tick(dt)` 推进衰减窗口；提供 `V` 供计分 |
| ComboScoring → CoreLoop | 读 | 输出 `m`（HUD/计分）、`combo`（供流速加成 `k_c`） |
| ComboScoring → 持久化 | 写 | 最佳记录、累计里程碑（D4） |

- **消费近失事件的接入点**：`onNearMiss(proximity)` 是 P2 的核心接口——obstacle-gen 在每个障碍通过玩家时计算最小净空 `d` 并 emit（三轨下带 `graze`/`flank` 子类），本系统按 `nearMissTier` 分档给 combo/加分。

## 7. 范围分层
- **MVP**：距离分（V×dt）+ 基础连击（仅补给 +1 + **相邻轨掠过近失 +1**）+ 本地最佳记录。无同轨贴脸分层(+2)、无星、无流速加成——保证早期不被倍率压迫（P3）。
  - **三轨 MVP 设计变更（相对原 2D 版）**：原 2D 版 MVP 完全无近失；三轨版因"相邻轨掠过近失 +1"零额外操作成本（任何 flank 障碍掠过即触发），且天然教玩家建立"贴脸/掠过"心智，故**提前在 MVP 引入该低风险 +1**；但高风险的同轨贴脸(+2)与急救包连击星仍延迟至核心档，维持 P2 早现与 P3 不劝退的平衡。
- **核心**：+ 同轨贴脸(+2) + 急救包（连击星，置于风险轨：常夹在障碍之间，收集需主动切到该轨穿针，呼应 P2）+ 倍率软封顶曲线 `m_max=5` + 技巧计分（二段跳）+ 跨局里程碑解锁（D4：累计距离 {1000,5000,20000}m→皮肤；最佳 {250,500,1000}m→称号；连击峰值 {20,40,80}→特效）。
- **延展**：每日挑战积分、异步排行榜（需后端）、连击特效升级。

## 8. 风险与开放问题
- **潜在主导策略（CONCERN，非阻塞）**：若相邻轨掠过恒 +1 且无代价，可能使"只呆在安全轨收 +1"成为低风险主导策略。缓解：高回报(+2/贴脸)仅来自同轨擦过（真实死亡风险）；且生成器须频繁封堵玩家当前轨逼迫反应（见 obstacle-gen 可解性约束）。需 playtest 校准近失带宽与"相邻轨横向净空"，使梯度真实。
- **车道几何常量缺口（NEW CONCERN，跨 GDD）**：`nearMissBand/Tier` 作为"壳间最小净空"在三轨下同时约束同轨擦过（可变 `d`）与相邻轨掠过（几何常量 `d`）。但车道几何（laneSpacingPx、playerHalfWidthPx、obstacleHalfWidthPx）尚未在任何 GDD/架构定义为常量，导致"相邻轨横向净空是否落在 band 内"目前不可验证。**建议**：新增 `LaneGeometry` 常量集（置于 `autoload/Tuning.gd`），并在 core-loop（或新增 LaneSystem GDD）定义"轨坐标↔世界/屏幕映射"。需主理人路由。
- **DOUBLE_JUMP 三轨语义（CONCERN，跨 GDD）**：空中二段跳在三轨背后视角下保留（core-loop 已明确定义），其计分事件保持核心档 +1；与 obstacle-gen §8 同步标注。
- **早期过载（CONCERN，非阻塞）**：MVP 关掉同轨贴脸/星，衰减窗口 `T` 在前期（前 ~5 局）建议放宽至 3.5–4s，随距离收至 2.5s，避免 P3 早期劝退。
- **R3 商业目标（已定 = 激励视频）**：核心档引入**激励视频**钩子（死亡复活 / 结算补给翻倍 / 里程碑额外奖励，频率上限防滥用，详见 core-loop §6.1）；MVP 无付费，补给解锁与里程碑并行，无强制付费（已保证无经济失衡）。
- **R4（已回签）**：HUD 刷新/分数显示非帧预算瓶颈，影响低；首屏包体口径=游戏资源 `.pck` <5MB，引擎 `.wasm` 经 CDN 缓存另计（与 core-loop/obstacle-gen 口径一致，主理人采纳推荐口径）。
