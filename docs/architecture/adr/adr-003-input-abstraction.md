# ADR-003 · 输入抽象层（触屏滑动 + 键盘）

- 状态：Accepted ｜ 作者：程基岩 ｜ 阶段：Phase 3
- 依赖：D3（触屏滑动）、P1（一指即达）

## 背景
D3 定操作=触屏单指滑动（上滑跳/下滑滑铲/贴墙蹬），桌面端映射键盘。P1 要求"不新增必须学才能玩的输入"。需统一多设备输入，避免玩法/UI 直接耦合具体输入设备，且 MVP 仅"上滑/下滑"两手势即可存活。

## 决策
- **InputManager（Autoload）** 为唯一输入入口，向上层只发**抽象动作事件**：`LANE_LEFT` / `LANE_RIGHT`（切轨，带方向）/ `JUMP`（上滑/↑，可选按住=高跳）/ `SLIDE`（下滑/↓）。
- **SwipeDetector** 处理触屏手势：仅识别**主指**，忽略第二触点；去抖用**最小位移阈值 + 最小时长阈值**防滚动误判。四向滑动：左滑=切左轨、右滑=切右轨、上滑=跳、下滑=滑铲。
- 键盘映射同动作事件：`A`/`←`=切左轨、`D`/`→`=切右轨、`W`/`↑`=跳（按住=高跳）、`S`/`↓`=滑铲。
- 玩法/Player 与 HUD **只订阅动作信号**，绝不读 `InputEvent` 原始设备。

### 三轨输入映射（2.5D 伪3D 身后视角）
> 与 architecture.md §6.2 / LaneSystem / PlayerController 对应；取代旧「2D 横版」的 WALL_KICK / HOLD 动作。

| 玩家意图 | 触屏手势 | 键盘 | 抽象动作 | 路由目标 |
|---|---|---|---|---|
| 切到左轨 | 左滑 | `A` / `←` | `LANE_LEFT` | `LaneSystem.switch_lane(-1)` |
| 切到右轨 | 右滑 | `D` / `→` | `LANE_RIGHT` | `LaneSystem.switch_lane(+1)` |
| 跳（矮/高） | 上滑（短/长按） | `W` / `↑`（按住=高跳） | `JUMP` | `Player` 运动学（重力/跳速） |
| 滑铲 | 下滑 | `S` / `↓` | `SLIDE` | `Player` 运动学（滑铲无敌帧） |

- **横向输入门控**：`LANE_LEFT` / `LANE_RIGHT` 在 **CORNER** 与 **REVIVE（RESULT）** 态被 `LaneSystem.set_input_locked(true)` 屏蔽（过弯强制中轨、复活态世界冻结）；`JUMP` / `SLIDE` 在 CORNER 仍生效（中轨仍需躲障碍），在 REVIVE 随整体冻结。
- **已退役动作**：旧 `WALL_KICK` / `HOLD` 属「2D 横版贴墙」语境，三轨身后视角无墙可蹬，已移除；`JUMP_LOW` / `JUMP_HIGH` 合并为单一 `JUMP`（按住时长映射跳高，保留 P1「复杂度来自组合而非新输入」）。
- 手势去抖阈值、切轨插值时长、按住高跳阈值均集中 `Tuning.gd`，留给 playtest 校准（CONCERN C7）。

## 理由
- 抽象层解耦设备，新增输入设备（如手柄）只扩展 InputManager，玩法零改动。
- 手势时序组合（二段跳=空中再上滑）与上下文复用（蹬墙）满足 P1"复杂度来自组合而非新输入"。
- 去抖 + 主指识别避免移动端误触/滚动，符合"一指即达"最低门槛。

## 后果
- 手势去抖阈值（最小位移/时长）需 playtest 校准（CONCERN，非阻塞）。
- 所有输入集中入口，调试与重映射集中；但要求全员遵守"只订阅动作"约定（control-manifest 检查项）。
